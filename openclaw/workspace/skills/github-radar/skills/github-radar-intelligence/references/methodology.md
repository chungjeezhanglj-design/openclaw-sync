# 方法与运行参考

## 数据来源

脚本调用 GitHub 官方 REST API 的 `GET /search/repositories`，按每条查询分别取回公开仓库，再以 `full_name` 去重。相同仓库命中多条查询时会保留全部命中词，用于解释主题覆盖度。

## 三榜定义

### 综合榜

综合分由两项 Min-Max 归一化信号加权：

- 存量分：`log(stars + 1)`，权重 0.4；
- 速度分：Stars 日增速，权重 0.6。

首次见到仓库时没有历史差值，速度使用 `stars / max(项目年龄天数, 1)` 估算。使用历史快照后，速度改为：

`max(当前 stars - 上次 stars, 0) / 两次观察间隔天数`

### 标杆榜

按 Stars 从高到低排序，取候选池前 5%，再受 `--top` 限制。该榜用于识别成熟、广泛采用的项目。

### 爆发榜

按日增速从高到低排序。首次运行的仓库全部可以进入候选；有历史快照时，真实日增速至少达到 `--burst-min-velocity` 才进入，默认阈值为 20 Stars/天。

## 快照格式

快照为 UTF-8 JSON：

```json
{
  "last_run": "2026-08-05T12:00:00+00:00",
  "repos": {
    "owner/repository": {
      "stars": 1200,
      "seen": "2026-08-05T12:00:00+00:00"
    }
  }
}
```

脚本只把仓库名、Stars 和观测时间写入快照，不保存 Token。

## 查询设计

优先使用简洁英文词组。一个主题通常使用 2–5 条查询：

1. 核心类别，例如 `AI agent framework`；
2. 同义表达，例如 `agentic workflow`；
3. 关键能力，例如 `multi agent orchestration`；
4. 垂直场景，例如 `browser automation agent`。

不要在查询中放真实凭证、个人隐私或未公开项目名。GitHub 支持的高级限定符可以直接写入查询，例如 `language:python`、`topic:rag`、`archived:false`。脚本会额外追加 Stars 下限。

## 限流与故障处理

- 未认证 Search API 限额较低；设置环境变量 `GITHUB_TOKEN` 可提高额度。
- 遇到短暂的 403、429 或 5xx 时，脚本会依据响应头做一次有限等待和重试。
- 单条查询失败不会丢弃其他成功结果，报告会列出警告。
- 所有查询失败或候选池为空时，脚本以非零状态退出。
- 认证失败时检查运行环境中的 Token；不要把 Token 复制到报告或 Skill 包。

## 解读边界

三榜适合发现候选项目，不替代代码审计。给出采用建议前继续检查许可证、最近提交、Issue 响应、依赖风险、维护者情况和项目文档。
