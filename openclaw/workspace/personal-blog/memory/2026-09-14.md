## 🐛 TypeORM 0.3.x + Node 26 ESM/CJS 坑

<!-- project: path:/Users/zhanglj/openclaw/workspace/personal-blog -->

- **症状**:`AppDataSource.initialize()` 时报 `module 'typeorm' does not provide an export named 'MigrationInterface'`
- **根因**:Node 26 用 `loadESMFromCJS` 加载 typeorm 0.3.x, ESM index.mjs 不导出 `MigrationInterface` named export
- **Workaround**:`backend/src/config/data-source.ts` 里**显式 import migration 类**而不是 glob `['src/migrations/*.ts']`
- 显式 import 走 CJS require 路径(`exports.require`),glob 走运行时懒加载触发 ESM
- **首次遇到时**:先把 `migrations: []` 拿掉快速验证 DB 连通,再换成显式列表
- 降 Node 到 20 也行,但当前 workaround 已足够

## 重要工程决策（长期适用）
- **TypeORM pin 0.3.17 exact**（不是 `^0.3.17`）。0.3.28 在 Node 26 下 ESM/CJS dual-load 丢 `MigrationInterface` export，触发 `SyntaxError: The requested module 'typeorm' does not provide an export named 'MigrationInterface'`。
- **`data-source.ts` 显式 import migration 类**，不用 glob `['src/migrations/*.ts']`。显式 import 在 require 阶段同步加载走 CJS，glob 在 `initialize()` 懒加载走 ESM 路径会踩坑。
- **3 个 migration 文件 `import` 原本被注释掉**——`1772198000000-CreateLogsTables.ts`、`1772200000000-AddLocationNameToBehaviorLog.ts`、`1772260000000-CreateGpsLocationCache.ts`。已修：拆成 `import type`（类型）+ `require()`（运行时）。

## 调试教训（避免重复踩坑）
- **`.env` 密码含 `$$` 必须单引号包**——shell 中 `$$` 是 PID变量。
- **幻觉教训**：我曾脑补密码 `19781206aB*#`，实际是 `19781206aB$$`。**以后引述文件内容前先 cat 一遍确认**，不靠记忆/推测。
- **edit 工具一次调用只能改一个文件**——多文件 edit 必须分开调用，混在一个 edit 数组里全 fail。
- **`vi.clearAllMocks()` 不清 `mockResolvedValueOnce` 队列**——跨测试污染，要用 `mockReset()`。
- **TypeORM 缺 migration 时 DB 通但 schema 不全**——加 `scripts/check-migrations.sh` 对比 `SHOW TABLES` 和预期。
